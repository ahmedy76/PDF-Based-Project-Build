# دليل Money Harmony — الحالة الحالية والاستخدام والنشر

> هذا المستند يصف ما هو موجود في التطبيق حاليًا، لا وعدًا بميزات مستقبلية أو شهادةً بنجاح النشر. التطبيق دفتر ميزانية أسرية عربي يعمل في المتصفح؛ إدخال الأموال ومتابعة الاستحقاقات يدوية حيثما ذُكر ذلك.

## الملخص التنفيذي

Money Harmony تطبيق ويب عربي متجاوب باتجاه **RTL** وخط Tajawal لإدارة دفتر الأسرة: حسابات بعملات مستقلة، معاملات دخل ومصروف، تحويلات داخلية، ميزانيات وتقارير، أهداف ادخار، ديون وأقساط، فواتير وتذكيرات **داخل التطبيق**. يمكن للمالك مشاركة الأسرة مع شريك والتحكم في صلاحياته ورؤية حساباته. تُسجَّل البيانات في قاعدة بيانات التطبيق؛ ليست شاشة نموذجية مؤقتة، لكن استمرارها في موقع منشور يتطلب تحققًا منفصلًا من النشر وقاعدة الإنتاج.

يُستخدم من متصفح سطح المكتب أو الهاتف أو الجهاز اللوحي. على الشاشات الكبيرة يظهر التنقل الرئيسي في أعلى الصفحة؛ وعلى الشاشات الأصغر يظهر شريط تنقل سفلي قابل للتمرير أفقيًا، مع وصول للإشعارات والإعدادات من الترويسة. **ليس** تطبيق Android APK أو iOS أصليًا أو برنامج سطح مكتب قابلًا للتثبيت؛ ولا يوجد في الوضع الحالي وعد بوضع PWA أو عمل دون اتصال.

### مصفوفة الحالة

| المجال | الحالة الحالية | حدّ التنفيذ |
| --- | --- | --- |
| إنشاء الحساب والأسرة والشريك | مُنفّذ | إنشاء حساب بالبريد وكلمة المرور، أسرة وفئات أولية، ورابط دعوة يُشارك يدويًا. |
| الحسابات والفئات والمعاملات | مُنفّذ | إدخال وتعديل يدوي، حسابات بعملة ثابتة وفئات دخل/مصروف قابلة للإدارة. |
| سجل تعديل المعاملات والتكرار | مُنفّذ | يسجل الأحداث الجديدة؛ القديم بلا سجل تعديلات بأثر رجعي. تُنشأ استحقاقات التكرار عند زيارة/تحديث الدفتر، لا بمجدول خلفي. |
| التحويلات بين الحسابات | مُنفّذ | بين حسابين نشطين ظاهرين من الأسرة **بالعملة نفسها فقط**؛ ليست دخلًا أو مصروفًا. |
| الميزانيات والتقارير | مُنفّذ | بحسب العملة والفترة، بلا تحويل عملات أو إجمالي مختلط. |
| الادخار والديون | مُنفّذ | أهداف وتخصيصات، ديون علينا/لنا وأقساط ودفعات يدوية؛ لا تُحرّك هذه السجلات أرصدة الحسابات تلقائيًا. |
| الفواتير وحالة السداد | مُنفّذ | إنشاء وعرض وتعديل وحذف، وتعليمها مسددة أو إعادتها لغير مسددة؛ لا قيد مالي تلقائي. |
| تذكيرات الاستحقاق | مُنفّذ داخل التطبيق | فواتير غير مسددة وأقساط **علينا** غير مسددة، عند زيارات صفحات محددة، مع تفضيل إيقاف؛ لا إرسال خارجي. |
| صلاحيات الشريك وحجب الحسابات | مُنفّذ | المالك يضبط الإضافة وتعديل الميزانيات ورؤية كل حساب؛ الخادم يطبق القيود. |
| ربط بنكي أو استيراد بنكي تلقائي | غير مُنفّذ | معاملات الدفتر يدوية. |
| بريد/SMS آلي للتذكيرات أو قائمة الإطلاق | غير مُنفّذ | وجود بريد مستخدم أو حقول قنوات في البيانات لا يعني وجود خدمة إرسال موصولة. |
| جدولة خلفية للتذكيرات أو تسجيل المعاملات المتكررة | غير مُنفّذ | التحديث مرتبط بزيارة/تحديث صفحات التطبيق المعنية. |
| تطبيق أصلي/PWA/عمل دون اتصال | غير مُثبت أو غير مُنفّذ | الوصول الحالي عبر متصفح متصل. |

## البدء وحساب الأسرة

1. من `/` يمكن الاطلاع على صفحة قائمة الإطلاق وتسجيل وسيلة تواصل بموافقة صريحة ثم اختيار تحديات الميزانية وقرار حجز عضوية المؤسسين أو النسخة المجانية؛ هذه الخطوات **ليست** إنشاء حساب أو دفعًا أو مراسلة آلية. تُحفظ وسيلة التواصل في الخطوة الأولى، ولا يمكن استكمال خطوات القائمة بعد إعادة التحميل دون آلية تحقق آمنة. رابط الإحالة `/?ref=...` اختياري، والمشاركة في واتساب يفتحها الزائر بنفسه؛ لا تعني نقرة المشاركة تسليم دعوة.
2. انتقل إلى `/register` لإنشاء حساب بالبريد الإلكتروني وكلمة المرور والموافقة على الشروط، أو إلى `/login` للدخول. ينشئ التسجيل أسرةً مبدئية وعضوية مالك وفئات دخل ومصروف مبدئية. صفحة `/onboarding` تعرض خيار إنشاء دعوة للشريك أو تخطي هذه الخطوة والانتقال للدفتر.
3. في `/accounts` أنشئ حسابًا ماليًا نشطًا وحدد نوعه وعملة ISO من ثلاثة أحرف ورصيده وتاريخ افتتاحه. العملة تثبت بعد الإنشاء. أنشئ فئات إضافية في `/categories` عند الحاجة ثم أدخل المعاملات في `/transactions`. يمكنك العودة لتحديث الدفتر من زر «تحديث الدفتر».
4. ادعُ الشريك برابط تُنشئه من واجهة الأسرة وتشاركه بنفسك. قبول الرابط في `/accept-invitation` يتطلب تسجيل الدخول بالحساب ذي البريد المقصود بالدعوة. لا يُرسل التطبيق بريد دعوة تلقائيًا. يستطيع المالك إدارة صلاحيات الأعضاء من `/settings`.

## صفحات التطبيق وكيفية استخدامها

| المسار | الاستخدام |
| --- | --- |
| `/` | صفحة التعريف وقائمة الإطلاق؛ يمكن استخدام إحالة اختيارية. |
| `/register`، `/login`، `/onboarding` | إنشاء الحساب، الدخول، ثم بدء دفتر الأسرة أو الدعوة. |
| `/dashboard` | ملخص الدخل والمصروف والأرصدة والميزانيات بعملة العرض، والمواعيد القريبة. |
| `/accounts` | إنشاء الحسابات، مراجعة أرصدة النشطة والمغلقة، إغلاق حساب مع بقاء تاريخه، والتحويلات الداخلية وسجلها. |
| `/categories` | إدارة فئات الدخل والمصروف وتسميتها وأرشفتها مع إبقاء السجلات السابقة. |
| `/transactions` | إضافة وتعديل وحذف معاملات الدخل والمصروف، التصفية، «إعادة استخدام البيانات»، سجل التعديلات، وقواعد التكرار. |
| `/budgets` | ميزانية شهرية لكل فئة مصروف وشهر وعملة وتحديد عتبة التنبيه. |
| `/reports` | تقارير فترة حالية أو سابقة أو آخر ثلاثة أشهر أو فترة مخصصة. |
| `/goals` | هدف ادخار وتخصيص مبلغ أو تحريره، وعرض السجل والأرشفة/الاستعادة. |
| `/debts` | ديون علينا ولنا، أقساط شهرية، دفعات يدوية، المتأخر والأرشفة. |
| `/bills` | سجل الفواتير: إضافة وعرض وتعديل وحذف، تعليم السداد والتذكيرات القريبة. |
| `/notifications` | الإشعارات وتذكيرات الفواتير والأقساط المستحقة قريبًا. |
| `/settings` | إعدادات الأسرة، تفضيلات إشعارات التطبيق وصلاحيات الشريك ورؤية الحسابات للمالك. |
| `/accept-invitation` | قبول رابط دعوة الأسرة بعد الدخول بالحساب المقصود. |

### الحسابات والمعاملات والتدقيق والتكرار

رصيد الحساب المسجل = الرصيد الافتتاحي + الدخل − المصروف − التحويلات الصادرة + التحويلات الواردة بالعملة نفسها. الإغلاق يُبقي سجل الحساب ورصيده بعملته، لكنه يخرجه من الحسابات النشطة ولا يُحوّل أمواله تلقائيًا. أنشئ فئة من النوع المناسب للدخل أو المصروف؛ أرشفة الفئة لا تمحو التاريخ، وقد تمنعها ميزانية جارية أو مستقبلية.

في المعاملات، اختر الحساب والفئة والنوع والمبلغ والتاريخ، ثم احفظ بنفسك. يمكن تصفية المعاملات بحسب النوع والحساب والفئة والتاريخ. قد يُقترح آخر حساب وفئة مناسبين، وزر «إعادة استخدام البيانات» يفتح نموذجًا جديدًا ببيانات سابقة **دون مبلغها ودون حفظ آلي**. «سجل التعديلات» يبين إضافة المعاملات الجديدة وتغييراتها الفعلية وحذفها مع المنفذ ووقت الحدث؛ المعاملات الأقدم لا تكتسب سجلًا تاريخيًا مفترضًا، وإن توفرت تُعرض بيانات إنشائها الأصلية. الاطلاع على السجل محصور بالأسرة والحساب المسموح به ولا يعرض بريد المنفذ.

يمكن إعداد معاملة متكررة يومية أو أسبوعية أو شهرية، وإيقاف القاعدة واستئنافها وتغيير مواعيدها القادمة دون تعديل المعاملات المسجلة سابقًا. تسجيل الاستحقاق يحدث عند فتح الدفتر أو تحديثه، وليس أثناء إغلاق الموقع بواسطة مهمة مجدولة. إغلاق الحساب أو أرشفة الفئة يوقف القاعدة تلقائيًا؛ يمكن تصحيحها ثم استئنافها.

### التحويلات والميزانيات والتقارير

من الحسابات، اختر حساب المصدر والوجهة والمبلغ والتاريخ وأي ملاحظة. يشترط حسابان مختلفان نشطان ظاهران للشريك المصرح له، من الأسرة نفسها وبالعملة نفسها، وتاريخ ضمن فترة افتتاح الحسابين وحتى اليوم. يُخصم المبلغ من المصدر ويُضاف إلى الوجهة؛ التحويل سجل مستقل لا يولّد معاملة دخل/مصروف ولا يغير نتائج تقارير الدخل والمصروف أو احتساب الميزانية. لا يوجد تحويل بين عملتين أو سعر صرف.

في الميزانيات، اختر فئة مصروف وشهرًا وعملة حساب نشط وحد الإنفاق ونسبة تنبيه. يُحتسب الصرف من حسابات تلك العملة فقط. تختار لوحة الدفتر والميزانيات والتقارير «عملة العرض» المشتركة؛ لا تجمع قيم العملات المختلفة. تدعم التقارير فترة حالية وسابقة وآخر ثلاثة أشهر وفترة مخصصة لا تتجاوز 366 يومًا، مع التحقق من التواريخ وعدم تجاوز نهاية الفترة اليوم.

### الأهداف والديون والفواتير

أهداف الادخار أسماء ومبالغ مستهدفة وتواريخ اختيارية؛ تخصيص الأموال أو تحريرها يدوّن **تقدم الهدف فقط**، ولا يُجري إيداعًا أو تحويلًا ولا يمس رصيد حساب أو تقارير الدخل والمصروف. الأهداف والديون مستقلة ومقومة بعملة الأسرة الأساسية، لا بعملة العرض المختارة.

في `/debts` سجّل دينًا «علينا» أو «لنا» مع الطرف والمبلغ وأول تاريخ استحقاق وعدد الأقساط الشهرية (1–120). يمكن بدء جدول دين سابق؛ المبالغ بدقة حتى أربع خانات عشرية وتوزيع الأقساط يحفظ إجمالي الأصل. تظهر المدفوعات والمتبقي والمتأخر وأول قسط غير مسدد. أضف دفعة جزئية أو مبكرة؛ تُطبّق على الأقساط بالتتابع. يمكن إلغاء دفعة بتأكيد مع إبقاء أثرها في سجل الدفعات وإعادة الحساب. بعد تسجيل أي دفعة، ولو أُلغيت، لا يمكن تغيير المبلغ أو النوع أو الجدول المالي؛ تبقى إمكانية تعديل العنوان والطرف والملاحظة. تُؤرشف الديون بعد سدادها الكامل فقط ويمكن استعادتها.

في `/bills` أنشئ فاتورة بعنوان ومبلغ وتاريخ استحقاق وحساب نشط ظاهر، وحدد أيام التذكير (0–365) وملاحظة اختيارية. عملتها تأتي من الحساب المرتبط؛ يمكن تعديل بياناتها أو حذفها. تعليمها «مسددة» يسجل حالة السداد وتاريخه، ويمكن إعادتها إلى «غير مسددة». حذفها يحذف سجلها وتذكيراتها المرتبطة. **الفواتير والديون ودفعاتها سجلات متابعة يدوية وليست قيودًا في دفتر المعاملات:** السداد أو القبض الفعلي لا يخصم أو يضيف رصيدًا تلقائيًا؛ سجّل حركة الدخل/المصروف الفعلية منفصلًا عند وقوعها، وتجنب تسجيلها مرتين.

### التذكيرات والإشعارات والصلاحيات

عند زيارة `/dashboard` أو `/notifications` أو `/debts` أو `/bills` تُحدّث تذكيرات التطبيق: فاتورة غير مسددة من اليوم إلى تاريخ الاستحقاق ضمن أيام التذكير المحددة لها؛ وقسط **دين علينا** غير مسدد من اليوم إلى ثلاثة أيام قبل موعده. لا تعني هذه الآلية استمرار التنبيه بعد مرور الموعد أو إشعارًا خارج المتصفح أثناء غياب المستخدم. يُحتفظ بسجل إيصال داخل التطبيق لمنع إنشاء تذكير مكرر لنفس المستخدم والاستحقاق والمصدر؛ يعاد حساب المبلغ المتبقي بعد دفعات الأقساط عند الزيارة. قد تظهر إشعارات أخرى للتعاملات والميزانيات؛ من `/settings` يمكن تشغيل/إيقاف أنواع إشعارات داخل التطبيق، ومنها تذكيرات الفواتير والأقساط. **لا** تفعّل هذه الإعدادات قناة بريد أو SMS.

يعرض المالك في الإعدادات صلاحيات كل شريك نشط: حق إضافة المعاملات، حق تعديل الميزانيات، وإتاحة/حجب الاطلاع على كل حساب على حدة. تبقى للمالك صلاحياته كاملة. يطبق الخادم القيود عند القراءة والحفظ: لا يرى العضو المحجوب عنه الحساب أو معاملاته أو قواعدها أو تحويلًا لا يرى طرفيه أو فواتيره وتذكيراتها أو أثره في أرصدته وإجمالياته وتقاريره؛ وتُخفى إشعارات الميزانية لعملة تضم حسابًا محجوبًا حتى لا تكشف نشاطه. الأهداف والديون المستقلة عن الحسابات لا تتأثر بحجب حساب. بيانات الأسر الأخرى غير متاحة عبر عضوية هذه الأسرة.

## الحدود الحالية وتصنيف المنصة

- التطبيق **ويب عبر المتصفح** بواجهة عربية متجاوبة على الحاسوب والهاتف واللوحي؛ لا يتوفر تثبيت أصلي APK أو iOS أو برنامج سطح مكتب، ولا وعد بـPWA أو مزامنة/استخدام دون اتصال.
- لا يوجد اتصال مباشر بالبنوك أو استيراد تلقائي للحركات؛ الإدخال يدوي. ولا يوجد تحويل عملات أو حساب أسعار صرف.
- لا يوجد إرسال آلي للبريد الإلكتروني أو SMS للتذكيرات أو الدعوات أو قائمة الإطلاق. وجود البريد في التسجيل أو أسماء قنوات ضمن البيانات لا يعني تفعيل مزود إرسال.
- التذكيرات وتسجيل استحقاقات المعاملات المتكررة مرتبطان بزيارة/تحديث صفحات التطبيق ذات الصلة؛ لا توجد خدمة جدولة خلفية مستقلة تضمن التنفيذ في يوم الاستحقاق عند عدم فتح التطبيق.
- تسجيل فواتير أو ديون أو تخصيصات ادخار لا يرحّل أموالًا إلى دفتر المعاملات ولا يتحقق من الدفع الحقيقي. يجب تسجيل الأثر النقدي الحقيقي بصورة منفصلة.

## أسئلة النشر والبيانات

**هل التطبيق متصل بقاعدة بيانات؟** نعم، توجد PostgreSQL مُدارة متصلة بهذا التطبيق في **بيئة التطوير الحالية**. تحقق تطويري للقراءة فقط نجح وقت التدقيق: 23 جدول تطبيق، مع وجود الجداول الأساسية للمستخدمين والفواتير والتحويلات وسجل إيصال التذكيرات. بلغ حجم قاعدة التطوير وقت التدقيق **10,846,208 بايت (نحو 10.35 MiB)**؛ هذا **حجم مستخدم** حينها، وليس حصة تخزين أو مساحة متاحة، ولا يثبت حالة الإنتاج. لا ندرج هنا بيانات وصول أو تفاصيل اتصال.

**هل أحتاج إلى ربط قاعدة منفصلة قبل النشر؟** في هذه البيئة، عادةً لا يلزم تكامل قاعدة منفصل لأن قاعدة مُدارة متاحة للتطبيق. مع ذلك تحقق من صفحة **Database** وحالة **Publishing** والخطة الفعلية، وتأكد من تطبيق الترحيلات الصحيحة على بيئة النشر. قد تكون بيانات التطوير وبيانات النسخة المنشورة منفصلة؛ لا تفترض أن سجلات المعاينة تظهر تلقائيًا في الإنتاج.

**هل ستبقى بيانات المستخدمين بعد إعادة التحميل أو إعادة تشغيل النسخة المنشورة؟** يُتوقع بقاء البيانات في قاعدة إنتاج مُدارة إذا نُشر التطبيق معها وكانت الترحيلات والاتصال وحالة الخدمة سليمة؛ لا يمكن تأكيد ذلك لهذه النسخة المنشورة دون اختبارها فعليًا. **لم يُتحقق من نشر الإنتاج بعد**. بعد النشر، أنشئ سجل تجربة غير حساس، أعد تحميل الصفحة وارجع إليه، ثم اختبر البقاء بعد إعادة تشغيل النسخة المنشورة إن أتاحت المنصة ذلك.

**ما السعة والنسخ الاحتياطية؟** لا يحدد هذا الدليل حصة تخزين أو سعة متاحة أو سياسة نسخ احتياطي/احتفاظ أو نجاح نشر مضمون. تتوقف على الاشتراك والمنصة والإعدادات الحقيقية؛ راجع **Database** والخطة و**Publishing** في واجهة البناء أو اسأل الجهة المشغلة قبل الاعتماد على التطبيق لتخزين بيانات مهمة. جهّز سياسة نسخ واستعادة واختبرها وفق ما توفره المنصة؛ لا تفترض وجود نسخ احتياطي تلقائي قابل للاسترجاع دون تحقق.

### قائمة قبول قصيرة قبل الاستخدام المنشور

- [ ] تأكد من نجاح النشر وعمل تسجيل الحساب والدخول والدعوة في بيئة النشر، لا في المعاينة فقط.
- [ ] تحقق من ارتباط قاعدة الإنتاج وتطبيق ترحيلاتها ومن إمكانية حفظ سجل تجربة وقراءته بعد إعادة التحميل/التشغيل؛ لا تنقل بيانات تطوير حقيقية افتراضيًا.
- [ ] اختبر عمليًا فصل الأسر، العملات، صلاحيات الشريك وحجب الحسابات، وحفظ الفواتير والتحويلات والتذكيرات دون تكرار.
- [ ] تحقق من سياسة الوصول والأمان والخطة والسعة والنسخ الاحتياطي وآلية الاستعادة في المنصة، وحدد مسؤولًا للمراجعة والاختبار الدوري.
- [ ] اختبر على متصفحات وأحجام شاشة وأجهزة فعلية وراجع إمكانية الوصول؛ الاختبارات البرمجية الحالية لا تحل محل اختبار المستخدم أو المتصفح ولا تثبت نجاح الإنتاج.

تتوفر اختبارات منطق وتكامل محدودة في المشروع، منها تحويلات الحسابات والفواتير والصلاحيات؛ قد تتطلب بعض اختبارات قاعدة البيانات اتصال تطوير متاحًا وتُتجاوز عند غيابه. تحقق قواعد الأعمال واختبارات القراءة وحدهما لا يثبتان أن النشر أو الإرسال الخارجي أو الاسترجاع من النسخ الاحتياطية نجح.
